# Parte 2: conversión a Forma Normal de Chomsky

Transformación final requerida por CYK. Recibe una gramática simplificada,
reemplaza los terminales dentro de cuerpos largos y descompone las producciones
de tres o más símbolos hasta obtener únicamente reglas CNF.

## Diseño

| Archivo | Contenido |
|---|---|
| `cnf.py` | `to_cnf_form(g)`, sustitución de terminales y descomposición de producciones largas. |
| `simplify.py` | `to_cnf(g)`: simplifica la gramática y luego llama a `to_cnf_form`. |
| `demo_p2.py` | Imprime la gramática simplificada, su CNF y un resumen de validación. |
| `tests/test_cnf.py` | 17 pruebas unitarias, de propiedades e integración. |

**Contrato**

- `to_cnf_form(g: Grammar) -> Grammar` recibe la salida de `simplify(g)`.
- La entrada no debe contener ε-producciones, producciones unarias entre
  variables ni símbolos inútiles.
- La función no modifica la gramática recibida: devuelve una nueva.
- El símbolo inicial, los terminales y el lenguaje se conservan.
- Cada producción resultante tiene forma `A -> a` o `A -> B C`.

El pipeline completo es:

```text
gramática -> eliminar ε -> eliminar unarias -> eliminar inútiles -> CNF
```

## Algoritmos

**Sustitución de terminales**

Si un terminal aparece en un cuerpo de longitud dos o mayor, se reemplaza por
una variable auxiliar `T_n`. La nueva variable produce únicamente ese terminal.

```text
S -> A + B              S -> A T_1 B
                        T_1 -> +
```

La misma variable se reutiliza cuando el terminal vuelve a aparecer. Las
producciones terminales válidas, como `A -> a`, no se modifican.

**Descomposición de producciones largas**

Un cuerpo de longitud `k >= 3` se reemplaza por una cadena de producciones con
dos variables. Se crean `k - 2` auxiliares `C_n`.

```text
A -> B C D E            A   -> B C_1
                        C_1 -> C C_2
                        C_2 -> D E
```

Cada cuerpo largo recibe auxiliares diferentes, incluso cuando comparte un
sufijo con otra producción.

**Nombres auxiliares**

Antes de generar nombres se recopilan todas las variables y terminales. Si
`T_1`, `C_1` u otro candidato ya existe, se avanza hasta encontrar un nombre
libre. El recorrido conserva el orden de la gramática, por lo que el resultado
es determinista.

## Ejemplo (`grammars/1.txt`, `python demo_p2.py`)

Después de eliminar ε-producciones, unarias y símbolos inútiles se obtiene:

```text
E -> T X | F Y | ( E ) | id
X -> + T X | + T
T -> F Y | ( E ) | id
Y -> * F Y | * F
F -> ( E ) | id
```

La conversión a CNF produce:

```text
E -> T X | F Y | T_1 C_1 | id
X -> T_3 C_2 | T_3 T
T -> F Y | T_1 C_3 | id
Y -> T_4 C_4 | T_4 F
F -> T_1 C_5 | id
T_1 -> (
T_2 -> )
T_3 -> +
T_4 -> *
C_1 -> E T_2
C_2 -> T X
C_3 -> E T_2
C_4 -> F Y
C_5 -> E T_2
```

`T_1` y `T_2` sustituyen los paréntesis, mientras que `T_3` y `T_4`
sustituyen los operadores. Las variables `C_1` a `C_5` descomponen los cuerpos
de tres símbolos. Aunque varias cadenas terminan en `E T_2`, cada producción
original conserva un auxiliar distinto.

## Pruebas

```bash
python -m unittest tests.test_cnf -v
python -m unittest discover -s tests -t . -v
```

- **Terminales**: reemplazo dentro de cuerpos largos, reutilización del auxiliar
  y conservación de producciones `A -> a`.
- **Producciones largas**: cuerpos de tres y cuatro variables, cantidad correcta
  de auxiliares y nombres diferentes para producciones diferentes.
- **Colisiones**: nombres `T_n` y `C_n` que ya existían como variables o
  terminales.
- **Propiedades CNF**: toda regla final es terminal o binaria, la entrada no se
  modifica y una gramática ya normalizada permanece igual.
- **Casos límite**: gramática sin producciones y lenguaje vacío.
- **Equivalencia**: enumeración y comparación de cadenas cortas antes y después
  de la conversión.
- **Integración**: conversión de `1.txt` y `english.txt`, composición con
  `simplify` y consumo de la salida por CYK en las pruebas de extremo a extremo.

## Discusión

- **Precondición**: `to_cnf_form` no elimina ε-producciones ni unarias. Esa tarea
  es de `simplify`. Para aceptar cualquier CFG se usa `to_cnf(g)`.
- **Identificación de terminales**: un símbolo es variable si aparece como cabeza
  de alguna producción, no se depende de mayúsculas o minúsculas.
- **Reutilización**: los auxiliares `T_n` se comparten por terminal para evitar
  reglas duplicadas. Los `C_n` no se comparten para mantener cadenas separadas.
- **Nombres únicos**: se revisan todos los símbolos, no solo las variables. Esto
  evita convertir accidentalmente un terminal existente en variable.
- **Gramáticas en CNF**: si la entrada ya está normalizada, no se agregan
  auxiliares ni se cambian sus producciones.
- **Cadena vacía**: el pipeline excluye `ε`, igual que la implementación de CYK
  utilizada en el proyecto.
