# Parte 1: lector de gramáticas, ε-producciones y unarias

Primera etapa de la simplificación de gramáticas. Su salida alimenta a la parte 2
(símbolos inútiles + CNF) y, después, a CYK (parte 3).

## Diseño

| Archivo | Contenido |
|---|---|
| `grammar.py` | Clase `Grammar` (`start` + `productions: dict[str, list[tuple]]`), `parse_grammar`, `load_grammar`, `GrammarError`. |
| `epsilon.py` | `find_nullable(g)` y `eliminate_epsilon(g)`. |
| `unit.py` | `find_unit_pairs(g)` y `eliminate_unit(g)`. |
| `useless.py` | `find_generating`, `find_reachable` y `eliminate_useless`. |
| `simplify.py` | `simplify(g)` (ε -> unarias -> inútiles) y `to_cnf(g)` (agrega la conversión a CNF de la parte 2). |
| `main.py` | Programa principal: SÍ/NO, tiempo de CYK y parse tree. |
| `demo_p1.py` | Imprime cada paso (para capturas del reporte). |
| `tests/test_p1.py` | 31 pruebas de parser, ε y unarias. |
| `tests/test_simplify.py` | 28 pruebas de inútiles, pipeline, utilidades de `main` y extremo a extremo. |
| `grammars/` | `1.txt`, `1-cnf.txt` (entregados) y `english.txt` (la del enunciado). |

**Contrato con las otras partes**

- Una producción `A -> X1 ... Xn` es `("X1", ..., "Xn")` dentro de `productions["A"]`.
  La cadena vacía es la tupla `()`.
- Variable = símbolo que aparece como cabeza de alguna regla; el resto son terminales.
- Las funciones no modifican la gramática de entrada: devuelven una nueva.
- Orden: `eliminate_useless(eliminate_unit(eliminate_epsilon(g)))`, que ya es `simplify(g)`.
- Parte 2 entrega `cnf.py` con `to_cnf_form(g) -> Grammar` (recibe la salida de `simplify`).
- Parte 3 entrega `cyk.py` con `parse(g_cnf, tokens) -> (bool, tree | None, seconds)`.
  Un árbol es `(símbolo, [hijos])` y una hoja es `(terminal, [])`.

**Formato de archivo**: una regla por línea, símbolos separados por espacios, `->` o `→`,
alternativas con `|`, `e` / `ε` para la cadena vacía, `#` para comentarios.

## Algoritmos

**ε-producciones**
1. Anulables por punto fijo: `A` es anulable si `A -> ε` o si todos los símbolos de
   algún cuerpo de `A` son anulables.
2. Por cada producción se agregan las `2^m` variantes que omiten subconjuntos de sus
   `m` símbolos anulables; la variante vacía se descarta.

El resultado genera `L(G) − {ε}`. Si el símbolo inicial es anulable, `ε` se pierde
(el ejemplo del curso procede igual y CYK en CNF no genera `ε`).

**Producciones unarias**
1. Pares unarios: `(A,A)` para toda variable; si `(A,B)` es par y `B -> C` es unaria,
   `(A,C)` es par (se recorre en BFS, así que los ciclos terminan).
2. Para cada par `(A,B)` y cada producción no unaria `B -> α`, se agrega `A -> α`.

**Símbolos inútiles** (`useless.py`)
1. Generadores: `A` genera si algún cuerpo tiene solo terminales o variables que generan
   (punto fijo). Se eliminan los que no, junto con toda producción que los mencione.
2. Alcanzables: se recorre desde el símbolo inicial y se eliminan los no alcanzables.

El orden importa: con `S -> a | B`, `B -> A b`, `A -> A a`, alcanzabilidad primero
dejaría a `A` y `B`; generadores primero los elimina. Si el inicial no genera nada, el
lenguaje es vacío y queda solo `S` sin producciones.

**Programa principal** (`main.py`)
`cargar gramática -> simplify -> to_cnf -> tokenizar -> cyk.parse -> imprimir`.
La frase se pasa en minúsculas (salvo que la gramática tenga terminales con mayúsculas)
y sin puntuación final; las palabras fuera del vocabulario se reportan. Opciones:
`-g archivo` (por defecto `grammars/english.txt`) y `--steps` (imprime original,
simplificada y CNF). Códigos de salida: 0 correcto, 2 error de uso/archivo.

## Ejemplo (`grammars/1.txt`, `python3 demo_p1.py`)

```
Original                     Sin ε                    Sin unarias
E -> T X                     E -> T X | T             E -> T X | F Y | ( E ) | id
X -> + T X | ε               X -> + T X | + T         X -> + T X | + T
T -> F Y                     T -> F Y | F             T -> F Y | ( E ) | id
Y -> * F Y | ε               Y -> * F Y | * F         Y -> * F Y | * F
F -> ( E ) | id              F -> ( E ) | id          F -> ( E ) | id
```

Anulables: `{X, Y}`. Pares unarios no triviales: `(E,T)`, `(T,F)`, `(E,F)`.
Coincide con la "Nueva G" del ejemplo manuscrito (con `X = E'`, `Y = T'`).

## Pruebas

```
python3 -m unittest discover -s tests -t . -v
```

- **Parser**: alternativas, `→`/`ε`, comentarios, cabecera repetida, duplicados,
  ida y vuelta `parse(str(g)) == g`, carga de las tres gramáticas, y errores de formato
  (sin flecha, cabeza múltiple, alternativa vacía, archivo vacío).
- **ε**: anulables directos, indirectos y negativos; las 4 variantes de `S -> A b A`;
  resultado exacto sobre `1.txt`; sin ε residual; gramática sin ε queda igual; entrada
  no mutada; `S -> ε` deja lenguaje vacío.
- **Unarias**: pares en cadena y en ciclo; eliminación de cadena y de ciclo; sin
  unarias residuales; pipeline exacto sobre `1.txt`; gramática inglesa sin cambios.
- **Equivalencia de lenguaje**: se enumeran todas las cadenas de hasta 5 o 6
  terminales de la gramática original y de la transformada, y se comparan
  (`L(G') = L(G) − {ε}`).

## Discusión

- **Quién es terminal**: no se distingue por mayúsculas, sino por no ser cabeza de
  regla. Así `id`, `+` y `(` funcionan sin convención especial.
- **`e` como ε**: es la notación de `1.txt`. Consecuencia: un terminal llamado
  literalmente `e` solo es válido dentro de una alternativa con más símbolos.
- **`|` como terminal** no está soportado (separa alternativas).
- **Explosión `2^m`**: una producción con muchos anulables genera muchas variantes.
  Es inherente al método y irrelevante para las gramáticas del proyecto.
- **Orden**: las unarias se eliminan después de las ε; si no, quedan unarias nuevas
  (p. ej. `E -> T X` con `X` anulable produce `E -> T`).
- **Aritmética con espacios**: para `grammars/1.txt` la frase se escribe con los
  símbolos separados (`( id * id ) + id`), porque el tokenizador separa por espacios.
- **Integración**: las pruebas de extremo a extremo verifican el pipeline completo, desde la simplificación y conversión a CNF hasta el reconocimiento mediante CYK.
