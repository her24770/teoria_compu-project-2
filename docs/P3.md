# Parte 3: algoritmo CYK y parse tree

## Diseño

La función pública `parse(g_cnf, tokens)` se encuentra en `cyk.py`. Recibe una
`Grammar` ya convertida a Forma Normal de Chomsky y retorna una tupla con:

1. `bool`: indica si la frase pertenece al lenguaje.
2. `tree | None`: contiene un parse tree si la frase fue aceptada, o `None` si
   fue rechazada.
3. `float`: tiempo empleado por CYK, medido en segundos con `perf_counter()`.

Un nodo del árbol se representa como `(símbolo, [hijos])`. Las variables de la
gramática son nodos internos y cada terminal es una hoja `(terminal, [])`. Por
ejemplo, `S -> NP VP`, `NP -> she`, `VP -> eats` produce:

```text
("S", [
    ("NP", [("she", [])]),
    ("VP", [("eats", [])])
])
```

## Algoritmo y tabla dinámica

Primero se crean dos índices de las producciones CNF:

- terminal `a` -> variables `A` tales que `A -> a`;
- pareja `(B, C)` -> variables `A` tales que `A -> B C`.

La tabla triangular se guarda como `table[inicio][longitud - 1]`. Cada celda
contiene las variables que generan esa subcadena y un backpointer por variable:

- `("terminal", token)` en el caso base;
- `("binary", corte, B, C)` si se usó `A -> B C`.

El caso base llena las subcadenas de longitud uno. Para longitudes de dos hasta
`n`, se prueban todos los inicios y todos los cortes posibles. La frase se
acepta si el símbolo inicial aparece en la celda que cubre todos los tokens.
Entonces se siguen los backpointers recursivamente para construir el parse tree.
Si existen varias derivaciones, se conserva la primera encontrada.

Para una frase de `n` tokens, el algoritmo realiza `O(n^3 * |P|)` operaciones
en la formulación tradicional. Los índices por pareja evitan recorrer todas las
producciones en cada combinación. La tabla y los backpointers ocupan
`O(n^2 * |V|)`.

## Ejemplos y pruebas

Con `grammars/english.txt`, después de simplificar y convertir a CNF:

Frases aceptadas:

- `she eats a cake with a fork`
- `the cat drinks the beer`
- `he cooks`
- `she cuts the meat in the oven with a knife`

Frases rechazadas:

- `cake the eats she` (orden sintáctico incorrecto)
- `the cat` (falta un predicado)
- `she eats with` (frase incompleta)
- `she eats a pizza` (`pizza` no pertenece al vocabulario)
- `the the cat drinks`

`tests/test_cyk.py` comprueba aceptación, rechazo, reconstrucción del árbol,
orden de sus hojas, gramática ambigua, token desconocido, entrada vacía,
medición de tiempo, validación de CNF y las gramáticas inglesa y aritmética del
proyecto. Para ejecutar toda la suite:

```text
python3 -m unittest discover -s tests -t . -v
```

Para probar el programa completo:

```text
python3 main.py "She eats a cake with a fork"
python3 main.py "cake the eats she"
python3 main.py -g grammars/1.txt "( id * id ) + id"
```

## Discusión

- El algoritmo requiere CNF. `parse` valida las formas `A -> terminal` y
  `A -> B C`, y lanza `ValueError` si recibe otra clase de producción. En el
  flujo normal, `simplify.to_cnf` realiza la conversión antes de llamar a CYK.
- Guardar solo booleanos permite reconocer la frase, pero no reconstruirla. Los
  backpointers agregan el corte y las variables hijas sin cambiar el orden
  asintótico del algoritmo.
- Una gramática ambigua puede producir más de un parse tree. El contrato pide
  un árbol, por lo que se guarda la primera derivación de forma determinista.
- CYK en la CNF usada por el proyecto no representa `ε`; por esto una lista
  vacía de tokens se rechaza.
- Las palabras desconocidas dejan vacía su celda base y la frase se rechaza de
  manera natural. `main.py` además informa cuáles palabras no están en la
  gramática.
- Los alias de tipos se escribieron con `typing` (`Tuple`, `Union`, ...) en lugar
  de `TypeAlias` y del operador `|` entre tipos, que requieren Python 3.10. Así
  el módulo funciona desde Python 3.9.
