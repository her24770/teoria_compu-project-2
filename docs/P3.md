# Parte 3: algoritmo CYK y parse tree

## Diseno

La funcion publica `parse(g_cnf, tokens)` se encuentra en `cyk.py`. Recibe una
`Grammar` ya convertida a Forma Normal de Chomsky y retorna una tupla con:

1. `bool`: indica si la frase pertenece al lenguaje.
2. `tree | None`: contiene un parse tree si la frase fue aceptada, o `None` si
   fue rechazada.
3. `float`: tiempo empleado por CYK, medido en segundos con `perf_counter()`.

Un nodo del arbol se representa como `(simbolo, [hijos])`. Las variables de la
gramatica son nodos internos y cada terminal es una hoja `(terminal, [])`. Por
ejemplo, `S -> NP VP`, `NP -> she`, `VP -> eats` produce:

```text
("S", [
    ("NP", [("she", [])]),
    ("VP", [("eats", [])])
])
```

## Algoritmo y tabla dinamica

Primero se crean dos indices de las producciones CNF:

- terminal `a` -> variables `A` tales que `A -> a`;
- pareja `(B, C)` -> variables `A` tales que `A -> B C`.

La tabla triangular se guarda como `table[inicio][longitud - 1]`. Cada celda
contiene las variables que generan esa subcadena y un backpointer por variable:

- `("terminal", token)` en el caso base;
- `("binary", corte, B, C)` si se uso `A -> B C`.

El caso base llena las subcadenas de longitud uno. Para longitudes de dos hasta
`n`, se prueban todos los inicios y todos los cortes posibles. La frase se
acepta si el simbolo inicial aparece en la celda que cubre todos los tokens.
Entonces se siguen los backpointers recursivamente para construir el parse tree.
Si existen varias derivaciones, se conserva la primera encontrada.

Para una frase de `n` tokens, el algoritmo realiza `O(n^3 * |P|)` operaciones
en la formulacion tradicional. Los indices por pareja evitan recorrer todas las
producciones en cada combinacion. La tabla y los backpointers ocupan `O(n^2 * |V|)`.

## Ejemplos y pruebas

Con `grammars/english.txt`, despues de simplificar y convertir a CNF:

Frases aceptadas:

- `she eats a cake with a fork`
- `the cat drinks the beer`
- `he cooks`
- `she cuts the meat in the oven with a knife`

Frases rechazadas:

- `cake the eats she` (orden sintactico incorrecto)
- `the cat` (falta un predicado)
- `she eats with` (frase incompleta)
- `she eats a pizza` (`pizza` no pertenece al vocabulario)
- `the the cat drinks`

`tests/test_cyk.py` comprueba aceptacion, rechazo, reconstruccion del arbol,
orden de sus hojas, gramatica ambigua, token desconocido, entrada vacia,
medicion de tiempo, validacion de CNF y las gramaticas inglesa y aritmetica del
proyecto. Para ejecutar toda la suite:

```text
python -m unittest discover -s tests -t . -v
```

Para probar el programa completo:

```text
python main.py "She eats a cake with a fork"
python main.py "cake the eats she"
python main.py -g grammars/1.txt "( id * id ) + id"
```

## Discusion

- El algoritmo requiere CNF. `parse` valida las formas `A -> terminal` y
  `A -> B C`, y genera `ValueError` si recibe otra clase de produccion. En el
  flujo normal, `simplify.to_cnf` realiza la conversion antes de llamar a CYK.
- Guardar solo booleanos permite reconocer la frase, pero no reconstruirla. Los
  backpointers agregan el corte y las variables hijas sin cambiar el orden
  asintotico del algoritmo.
- Una gramatica ambigua puede producir mas de un parse tree. El contrato pide
  un arbol, por lo que se guarda la primera derivacion de forma determinista.
- CYK en la CNF usada por el proyecto no representa `epsilon`; por esto una
  lista vacia de tokens se rechaza.
- Las palabras desconocidas dejan vacia su celda base y la frase se rechaza de
  manera natural. `main.py` ademas informa cuales palabras no estan en la
  gramatica.
